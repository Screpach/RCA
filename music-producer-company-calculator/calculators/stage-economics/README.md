# Stage Economics v3

Автономный webapp для расчёта экономики концерта или спектакля. Сервер и интернет не требуются: Plotly включён локально.

## Запуск

Обычная версия:

1. Распакуйте ZIP полностью.
2. Откройте `index.html`.

Автономная версия одним файлом:

- откройте `single-file.html`;
- CSS, JavaScript и Plotly уже встроены внутрь.

Для локального web-сервера:

```bash
python -m http.server 8080
```

После этого откройте `http://localhost:8080`.

## Валидация без искусственных максимумов

Искусственные верхние лимиты для аренды, бюджетов, гонораров, артистов, дней, цены билета, hotelling и K удалены. Остались только условия, необходимые для математически корректного расчёта:

- вместимость — целое число больше нуля;
- денежные расходы и ставки — неотрицательные;
- количество дней и артистов — неотрицательные целые числа;
- K — больше нуля, без верхнего предела;
- загрузка — от 0% до 100%;
- Ticketmaster — от 0% до значения строго ниже 100%;
- tornado-шок — 0–100%;
- дата концерта должна быть существующей календарной датой.

Пустое или некорректное поле не заменяется нулём и не обрезается. До исправления поля приложение сохраняет последний корректный результат.

## Расчёт аренды

Поддерживаются три режима:

- **A:** введённая сумма уже является «всё включено + IVA 21%»;
- **B:** `roundup₀․₁(введённая сумма × 1,21)`;
- **C:** `roundup₀․₁(введённая сумма ÷ 0,66 × 1,21)`.

В таблице затрат показываются фактически выбранный режим и применённая формула.

## Реклама и календарь

Пользователь выбирает дату концерта и количество календарных дней рекламной кампании. Приложение показывает:

- дату старта рекламы;
- полную продолжительность;
- оставшееся количество дней;
- предупреждение, если старт уже прошёл;
- предупреждение для прошедшего концерта.

Разница дат рассчитывается по календарным дням через UTC-day index, поэтому переходы на летнее/зимнее время не изменяют результат.

Для месячной ставки доступны три метода:

- стандартные 30 дней;
- среднее `365 / 12`;
- фактическая доля каждого затронутого календарного месяца.

Возле агентской и digital-ставки показываются введённая сумма, IVA, ставка с IVA и стоимость за весь период.

## Округление расходов

Каждый самостоятельный оплачиваемый компонент округляется **один раз вверх до €0,10**, после чего компоненты складываются:

- аренда;
- агентство за период;
- digital за период;
- гонорары за спектакль;
- репетиции;
- пакет расходов;
- hotelling;
- билетный IVA;
- Ticketmaster;
- IN-03.

Рабочая цена билета также округляется вверх до €0,10 **до** расчёта выручки и сценариев.

## Hotelling и финальный brutto

Основная формула:

```text
Direct + roundup₀․₁((0,03025 × Direct + 1,4641) / 1,06975)
```

В основном формульном расчёте hotelling применяется к полной вместимости. В сценариях и таблице загрузки он применяется к фактически проданным билетам; обе базы явно подписаны.

Циклическая зависимость hotelling не решается случайной итерацией. Алгоритм:

1. аналитически проверяет, существует ли конечная цена;
2. рассчитывает аналитическую оценку;
3. строит безопасную числовую скобку без бизнес-лимита цены;
4. находит решение на дискретной сетке €0,10;
5. обнаруживает цикл округления или переполнение и выводит причину вместо случайного результата.

## Ticketmaster и IVA

Основа Ticketmaster выбирается пользователем:

- цена билета без IVA — значение по умолчанию;
- brutto-цена билета.

Комиссия рассчитывается от точной выбранной основы, затем итоговая комиссия округляется вверх до €0,10.

## Безубыточность и K

Безубыточная цена сначала оценивается аналитически, затем уточняется защищённым дискретным поиском с шагом €0,10.

```text
K = рабочая цена / цена безубыточности
```

- `K < 1` — возможный минус;
- `K = 1` — точка безубыточности;
- `K = 1,25` — целевой уровень;
- верхнего лимита K нет.

Если конечной цены безубыточности не существует, продано 0 билетов или знаменатель K равен нулю, приложение показывает **«K недоступен»** с причиной и не подменяет значение формульной ценой.

В ручном режиме отдельно показываются целевой K и фактический K введённой цены.

## Сценарии

По умолчанию используется сетка по уровням K. Доступен legacy-режим множителей рабочей цены.

Всего строится 216 сценариев:

```text
6 цен × 6 загрузок × 3 уровня гонорара × 2 уровня пакета
```

Основная таблица показывает:

- все прибыльные сценарии;
- не более 12 отрицательных сценариев с остатком, ближайшим к нулю.

Любой столбец сортируется по возрастанию или убыванию. Приоритеты отмечены в интерфейсе:

1. операционный остаток;
2. маржа;
3. фактический K.

Доступны отдельные экспорты:

- CSV текущей отфильтрованной выборки;
- CSV всех 216 сценариев.

## Таблица загрузки 0–100%

Таблица содержит 21 строку с шагом 5% и показывает:

- целевую загрузку;
- фактическую загрузку после округления количества гостей;
- проданные места;
- цену и фактический K;
- brutto-выручку;
- IVA и Ticketmaster;
- hotelling;
- фиксированные и переменные расходы;
- общие расходы;
- netto-выручку;

При 0 проданных билетов K и маржа выводятся как `—`. Первая строка, пересекающая безубыточность, выделяется. CSV содержит также дату концерта, старт рекламы и все выбранные параметры.

## Аналитические панели

Реализованы 24 модуля и 25 Plotly-панелей. Добавлены:

- настоящий contour `z = 50%` на heatmap положительных вариантов;
- contour нулевого результата на финансовых heatmap;
- reference line на фактической позиции сценария P5;
- явное сообщение «Невозможно рассчитать при 0 проданных билетов»;
- автоматическая замена любых нечисловых координат на `null` перед передачей Plotly;
- сообщение при отсутствии `plotly.min.js`.

Все панели поддерживают штатные функции Plotly: hover, масштабирование, перемещение, переключение серий и PNG-экспорт. Scatter-панели позволяют выбрать сценарий кликом.

## MCDA

Резервный режим использует 25 детерминированных прогонов весов по пяти критериям и явно маркируется как proxy.

Импорт поддерживает:

### JSON weights

```json
{
  "type": "weights",
  "runs": [
    [0.3, 0.24, 0.16, 0.16, 0.14]
  ]
}
```

Массив `runs` должен содержать ровно 25 строк по 5 неотрицательных весов.

### JSON ranks

```json
{
  "type": "ranks",
  "rows": [
    {"id": "P1", "ranks": [1, 2, 1, 3]}
  ]
}
```

Для применения ко всей текущей модели каждый сценарий должен иметь 25 рангов.

### CSV weights

25 строк × 5 чисел, разделитель `;`, табуляция или `,`.

## Сохранение и перенос проекта

- состояние хранится в versioned `localStorage` версии 3;
- старое состояние v1/v2 мигрируется;
- кнопка «Удалить данные» полностью удаляет сохранённые параметры и MCDA;
- проект экспортируется и импортируется в JSON вместе с MCDA-конфигурацией.
